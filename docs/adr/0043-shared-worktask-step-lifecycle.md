# ADR 0043：WorkTask 步骤生命周期共用转换合同

## 背景

持久 WorkTask 已支持预处理和统计 Run，但这两类步骤分别实现了用户授权启动时的 `READY → RUNNING → WAITING` 绑定过程。步骤状态变化、任务状态变化和 Run 引用应遵循相同生命周期；预处理 Artifact/lineage 与统计结果/设计的核验则必须保留各自领域合同。把二者继续写在一个服务的大型条件分支中，会让新步骤类型难以扩展，也容易在重复启动、并发写入或恢复时产生状态差异。

## 决策

在 `application/automation/` 定义传输无关的纯步骤生命周期转换。用户已确认并成功创建受控 Run 后，预处理与统计用例调用同一转换：精确匹配等待用户的 WorkTask、唯一且就绪的 TaskStep、冻结输入与 Run 绑定；步骤进入 `WAITING`，任务进入 `WAITING_RUN`，并同时保存 Run 引用。重复请求只在任务与步骤均绑定同一 Run 且状态一致时幂等返回；另一 Run、错误步骤、非法状态或引用冲突均失败关闭。转换函数只返回不可变的新状态，不访问数据库、模型、文件或执行器。

步骤完成也通过共享纯转换表达：调用方必须先由步骤专属检查器读取权威对象并验证冻结输入、项目归属和目标证据；转换只将匹配的等待步骤标记成功、写入已经核验的 Artifact 引用并更新任务完成状态。唯一允许关闭 `WAITING_USER` 的完成路径，是步骤仍绑定同一 Run 且任务正等待该 Run 的 `qc:<run_id>` 决定；只有调用方先核验到权威 QC 批准或显式跳过记录及全部目标 Artifact 后，才能使用该转换。统计方案审查等其他用户等待不能借此完成。事务、乐观版本检查、Worker claim fencing、结果解释 outbox 与分析提案 outbox 仍由现有应用服务和 SQLite Unit of Work 负责。步骤检查器不能让状态转换器代替科研校验。

首个实现只接入 `preprocessing_run` 与 `statistical_run`。未知步骤类型、多个无法唯一绑定到当前 Run 的候选步骤，以及不完整的引用不得按默认分支当作预处理步骤或标记完成；没有可用检查器时只能停在 dependency/`indeterminate` 并说明缺少何种核验。新增步骤类型须注册自己的只读权威检查器，并复用生命周期合同。

在通用多步骤推进器落地前，含显式 `TaskStep` 的 Run 绑定/重核/完成仅支持恰好一个已注册 Run 步骤。未知、混合、多步骤或 Task/Step Run 引用不一致的记录在重核入口以 `indeterminate` 失败关闭，且不会先消费新事件；用户启动绑定和纯生命周期完成也拒绝此类步骤集合。没有显式步骤的历史任务暂保留兼容读取路径，但不能由共享的类型化步骤完成器完成。任务完成不得把未完成的 sibling step 隐式视为成功。

本 ADR 不引入任意 DAG 调度、并行 fanout、多分析目标身份、自动审批 QC/Plan、自动创建或重试 Run，也不把模型调用放入事件重核协调器。后续多指标或多分析分支需另行规定独立方案、审批、运行、结果、部分失败和恢复身份。

## 后果

现有两类运行的状态转换可以用同一组纯函数和不变量验证，同时保留预处理与统计的专属证据校验。自动化核心逐步从步骤专属代码中解耦，为后续恢复处理器注册和下游步骤准备提供稳定边界；本 ADR 本身不宣称任意多步骤任务已经可自动调度。
