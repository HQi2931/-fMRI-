# ADR 0010：持久化上下文工程

状态：接受

## 背景

Chat Phase 1 只把最近 12 条消息和本次检索证据发送给模型。长对话会丢失早期约束，Work 模式也没有复用统一的上下文选择与审计机制。

## 决定

- Chat 和 Work 共用 `ContextEngine`，按模型窗口对当前问题、摘要、记忆、最近消息、证据和工作状态分配预算。
- 会话超过阈值后生成滚动摘要；Chat 优先使用当前模型，Work 使用确定性摘录。
- 用户偏好可以自动确认，科学参数只生成待确认候选；项目、计划、运行和 QC 状态继续以业务数据库为唯一真源。
- SQLite 保存摘要修订、记忆记录和脱敏结构化快照。快照只记录来源、预算、裁剪结果和哈希，不复制完整正文。
- 记忆限制在会话或项目作用域内，不提供跨项目召回。

## 后果

长对话可以在固定预算内保留已确认约束，用户能够查看和管理记忆。模型配置需要声明上下文窗口和回答上限，旧配置使用兼容默认值。上下文构建增加少量数据库读写，并只在达到摘要阈值时增加一次模型调用。
