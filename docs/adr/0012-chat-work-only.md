# ADR 0012：前端只保留 Chat 与 Work 对话

## 状态

已接受，2026-09-18；取代 ADR 0011 的消息操作卡片方案。

## 背景

ADR 0011 已把独立业务页面收敛到 Work，但仍保留能力目录、消息卡片、草稿版本和卡片操作接口。它把同一业务状态同时表达为对话、卡片草稿和服务端对象，界面仍然复杂，也偏离“所有功能从 Work 对话自然发起”的目标。

## 决策

1. 前端主导航只有对话工作台，工作台只呈现 Chat 与 Work；设置继续使用独立 `/settings` 地址。
2. 删除独立业务页面、卡片组件、能力目录、卡片草稿及卡片操作 API。旧业务地址和未知地址只渲染同一个 Work 工作台。
3. Work 自然语言由确定性协调器解析为闭集 `ConversationAction`，再调用现有应用服务。对话层不接受任意组件名、Shell、MATLAB 文本或科学执行代码。
4. 对话消息只展示参数摘要、确认要求、运行状态和结果文字；权威状态仍是服务端 Project、Dataset、Manifest、PlanRevision、WorkflowInstance 与 Artifact。
5. 科学参数、不可变计划哈希、人工批准和逐次真实执行确认继续失败关闭。当前 DemoData ALFF 路径是窄且显式的受控配方，不是可以猜测参数的通用 Agent。

## 后果

用户只需理解 Chat、Work 和设置，刷新后可从持久化会话及活动运行恢复。前端不再承担复杂表单和卡片状态，但通用科研任务仍需逐步扩展对话动作和类型化请求；未登记意图只能澄清或说明，不能直接执行。既有底层 REST 业务接口继续保留，删除的仅是 Work 卡片能力目录与卡片动作接口。
