# ADR 0019：对话正文流式预览与事务收口

- 状态：Accepted
- 文档类型：ADR
- 维护者：system_architect
- 决策日期：2026-09-29
- 更新日期：2026-09-29
- 关联：[对话流式计划](../plans/0010-conversation-streaming.md)、[ADR 0015](0015-agent-control-plane-hardening.md)

## 背景

Chat 和 Work 原来等待完整模型响应。Work 的响应包含受严格校验的动作 JSON；直接向前端输出原始增量会混入参数、工具及授权字段。现有异步幂等协议还要求断连后继续收口已派发的 Provider 请求。

## 决定

复用 `POST /conversations/{id}/turns`，仅 `stream=true` 切换为 SSE。模型边界提供请求隔离的正文观察器，Provider 在声明 streaming 能力时采用原生 SSE，否则返回完整正文。内部意图、摘要及记忆调用不进入正文流。Work 只提取顶层 answer 字符串作为暂存预览；所有动作仍等待完整 JSON 校验与服务端处理。

正文使用 delta，模型回退和工具轮次使用 reset。最终会话、引用、草稿、工具步骤在原事务内保存成功后通过 final 返回。流中的 error 使用稳定错误封装，不暴露异常原文。流断连停止事件发送，既有幂等操作继续执行并保存结果；重试同键返回已保存的 final。

## 后果

增量内容属于尚未校验的预览，最终内容可能因引用清理或 Work 校验被替换。SSE 响应头发送后，应用错误通过事件返回，不能再更改 HTTP 状态。前端必须检测缺失 final，保留幂等键并允许显式重试。流式传输不增加模型的执行权限。

## 替代方案

前端对完整回答逐字动画无法缩短等待首字的时间。直接公开 Work JSON 会混入业务字段。独立的新端点会增加幂等范围与客户端维护成本，因此沿用原接口。
