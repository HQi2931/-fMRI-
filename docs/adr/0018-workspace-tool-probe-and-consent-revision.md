# ADR 0018：工作区文件授权验证具体模型工具能力

- 状态：Accepted
- 文档类型：ADR
- 维护者：system_architect
- 决策日期：2026-09-27
- 关联：[ADR 0014](0014-bounded-tool-loop.md)、[Provider 配置与 smoke](../operations/provider-setup.md)、[模型数据外发策略](../security/data-egress.md)

## 背景

Work 的工作区文件工具已经存在，但 Profile 能力声明没有在设置页提供 `tool_use` 选项。即使用户显式选择具体模型，服务端也只能依据配置声明判断是否进入工具调用循环；服务商 `/models` 返回模型名称不能证明该模型支持 function calling。工作区授权长期绑定 Profile ID 和模型名，也无法识别同 ID Profile 被修改或删除重建后的配置变化。

## 决定

1. `tool_use` 仍是 Profile 级人工能力声明；设置页允许编辑已绑定 Profile 的能力，默认不替现有配置开启该能力。
2. 用户显式点击工作区文件授权后，服务端向被选中的具体模型发送一次合成、无副作用的工具调用请求。探针不包含工作区路径、文件名、文件内容或会话对话，也不派发返回的工具调用；只有精确返回探针工具及空参数才建立授权。探针失败、超时或 Profile 未声明 `tool_use` 时失败关闭。
3. 授权记录绑定 Profile 配置修订、具体模型、规范工作区和策略版本。每轮提供工作区工具前服务端复核这些信息及能力声明。Profile 配置修订变化、工作区变化或用户撤销都会使授权不可用；旧迁移记录不自动继承授权。
4. 兼容性测试与工作区内容授权共用授权按钮。UI 先展示外发范围并取得用户确认，然后执行探针；确认探针成功后，后续文件读取仍仅通过现有受限 READ 工具和内容脱敏器。

## 后果

- 设置中的 `tool_use` 代表用户对 Profile 下工具能力的声明，不能替代对具体模型的探针结果。
- 对不支持工具调用的模型，Work 普通对话继续可用，但不会提供工作区内容工具。
- Profile 更新会要求用户重新授权；探针会产生一次外部模型请求，可能产生服务商费用，但不携带文件数据。
- Profile 配置修订哈希仅由非密钥配置、Profile 版本和创建时间计算；授权审计记录不保存探针原文或工作区文件内容。
