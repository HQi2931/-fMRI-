# Work 候选方案与直接界面确认

- 状态：Accepted
- 文档类型：ADR
- 维护者：system_architect
- 决策日期：2026-10-07
- 关联：[计划 0012](../plans/0012-work-conversation-ux.md)、[ADR 0015](0015-agent-control-plane-hardening.md)、[ADR 0018](0018-work-confirmation-dialog.md)

## 背景

递归参数清单、手输技术口令及重复模型往返增加方案审查负担。参数齐全后应自动准备候选方案，再由用户明确批准启动。自动编译不能伪造用户已经确认科学选择。

## 决策

候选方案使用独立的 `proposal` 参数来源；该来源允许编译待审查方案，但不代表用户批准或扫描事实。界面分别展示数据读取、系统计算、用户指定和模型推荐，以及独立的校验状态。方案级审批仍单独记录。

界面通过 `work-confirmation` 提交服务端签发的操作及当前草稿哈希，协调器复用既有一次性挑战、事务和幂等机制，不要求模型解释启动意图。`work-review` 允许不调用模型地重新准备审查或更新确认。缺失、冲突、版本变化、挑战过期及作用域不符继续阻断启动。EXECUTE 不进入模型工具目录。

普通只读数据概况只检查目录、大小和必要头信息，不计算全部文件内容哈希。冻结输入清单、启动前校验和产物登记的完整性检查继续保留。

## 后果与验证边界

这是 ADR 0018 确认传输与展示方式的补充；历史记录和旧确认路径仍可读取，ADR 0015 的执行授权边界保持有效。新增接口与生成类型同步维护。阶段单元和组件验证不等同于完整并发、断线恢复或真实网页计算验收；剩余验收按计划 0012 执行。
