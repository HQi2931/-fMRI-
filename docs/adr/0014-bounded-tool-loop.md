# ADR 0014：有界工具调用循环与三级工具契约

- 状态：Accepted
- 文档类型：ADR
- 决策日期：2026-09-23

## 背景

在此之前的 Agent 只有一次模型调用：模型收到一个结构化摘要，返回一个固定枚举中的 `action` 加一段 `draft_patch`。这个形态有两个问题。

第一，模型无法在回答前获取信息。Chat 只能凭空回答或依赖一次性前置检索；Work 只能依赖服务端预先塞进 `work_context` 的状态。需要多步才能得到的结论（先查 QC，再看产物，最后判断能否统计）无法由模型自己完成。

第二，模型可选择的动作与服务端可执行的动作共用同一个名字空间。`ConversationAction.START_PREPROCESSING` 既是 REST 入口，也曾是模型可以输出的 `action` 取值。它当时无法自行授权（授权来自服务端签发的精确口令），但**能选中**与**不能选中**之间的差别只由一处调用方检查维持，而不是由结构保证。

## 决定

引入有界的工具调用循环，并把工具按**权威层级**分为三级：

- **Tier A `READ`**：只观察状态，模型可自由调用，结果回灌上下文。
- **Tier B `PROPOSE`**：只能写草稿、修订和提案，绝不启动计算。
- **Tier C `EXECUTE`**：启动或批准真实工作。

关键点是 **Tier C 工具在目录构建阶段就被丢弃**，而不是在派发阶段被拒绝。`build_model_visible_catalog()` 只保留 READ/PROPOSE；`ToolDispatcher` 再从该目录构建绑定，并在派发时二次校验层级。因此一个越权工具**根本没有进入 provider 请求的路径**，模型即便猜到名字也找不到可调用的对象。

循环本身有硬上界：步数、墙钟、token 三重量，加上「连续同名同错误码失败」熔断。工具结果一律包装为不可信数据并在系统提示词中声明。循环的停止原因是显式枚举（`AgentLoopStopReason`），因此「预算耗尽」与「已完成」在审计上是可区分的。

Work 侧的动作集合改由 `work_actions.py` 单一维护，`WorkInterpretation.action` 校验集合成员而不再是手写字面量；`resolve_action()` 的关键词回退路径只允许返回 READ/PROPOSE 动作。原 `start_preprocessing` 改名 `propose_run_confirmation` 并降为 PROPOSE：它只渲染那条需要用户本人手打的确认指令，因此既保住了「用户说要开始」的识别能力，又消除了与 EXECUTE 动作重名的隐患。

Work 的循环只提供**只读**工具：运行状态、运行产物类型汇总、已登记统计结果、多重比较校正能力、Skill 清单。`work_context` 已经携带运行/QC/方案状态，因此这些工具刻意不重复它，只补充它没有的状态。循环的最终文本就是 Work 原有的 JSON 契约，所以解析、`WorkInterpretation` 校验和整条授权路径完全未改；循环若产出不可解析的文本，则回退单次路径重试——**JSON 模式由回退路径保证，而不是由循环保证**。

工具轮次不再附带 `response_format: json_object`：模型必须能自由地以 `tool_calls` 作答，而且多数 OpenAI 兼容网关拒绝两者组合。

审计随会话轮次**在同一事务内**落库：`ToolCallOutcome` 自带已脱敏的入参，`append_conversation_exchange(tool_calls=...)` 与消息一起写入，避免循环轨迹写一半；`0014_agent_tool_loop` 增加 `step_index`/`risk_tier`/`provider_call_id`/`duration_ms`，并按 `step_index` 排序以保证展示顺序等于执行顺序。

## 后果

- 模型不再能命名任何启动、批准、跳过或建立工作区的动作。这一性质由模块导入时的 `check_tier_boundary()` 与测试共同守护。
- 未声明 `ModelCapability.TOOL_USE` 的模型走原有单次路径，行为不变；工具循环是增量能力而非替换。
- 工具结果重新进入模型上下文，因此引入了新的外发面。缓解是双重的：`redact_tool_result()` 对机器结构化结果采用「无法证明安全的叶子字段丢弃并计数」的分级策略（用户自由文本仍是整体拒绝），同时结果被标记为不可信数据并声明为数据而非指令。
- 工具必须自行限制输出规模。脱敏策略拒绝超过 100 项的列表与超过 20k 字符的字符串，因此返回长清单的工具需要分页或只返回摘要加总数，这是契约束缚而非缺陷。
- ChatAgent 的既有引用守卫仍然生效：循环产出的回答同样要经过无效 `[Cn]` 剔除，且收集器在插入时分配编号，保证模型在工具结果中看到的编号与最终引用一致。
- 循环在无产出时（预算耗尽、provider 失败）回退到单次路径，因此用户不会因为循环未完成而收到空回答。
