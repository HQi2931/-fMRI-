# ADR 0037：fMRI 输入身份与证据来源

- 状态：Accepted
- 文档类型：ADR
- 维护者：system_architect
- 决策日期：2026-10-12
- 关联：[计划 0014](../plans/0014-general-agent-automation.md)、[数据集输入契约](../domain/dataset-contract.md)、[外部统计输入 ADR](0025-external-statistical-inputs.md)

## 背景

静息态 fMRI 的数据不总按单一目录布局组织。单组输入、条件成对图像、人口学表驱动分组、多 session/run 和已完成中间阶段都需要明确身份和来源；仅凭目录层级或文件名推断身份会造成受试者错配或重复计数。

## 决策

输入映射以显式身份元组表达 `subject_id`、`session_id`、`run_id`、`modality`、`condition`、`metric` 和 `scale`。字段可缺失，但缺失必须保持为 unknown，不能由默认目录顺序填补。跨表、影像、条件和协变量的绑定以稳定身份键完成，不以排序位置连接。

每项影响科学解释的身份、空间、采集参数和处理史都记录来源及证据级别，例如执行器核验、用户声明、候选推断或 unknown。文件名、目录名和 header 可产生候选，但不能单独把候选升级为执行器核验。相互冲突的证据须保留并呈现，需研究者选择时不得静默取舍。

目录检查只读原始数据。系统可以提出输入映射和表列绑定草稿，正式统计设计必须冻结映射版本、源文件身份/哈希及显式的受试者与条件关系。多 session/run 必须先识别重复测量结构；当前执行器未支持的设计应在执行前阻断，不得把每个 scan 当作独立受试者。

## 后果

单组、平铺目录和人口学表驱动输入可以逐步接入同一套显式映射合同，外部导入不再要求伪造多个组目录。向后兼容的适配器可以从现有数据构造候选映射，但必须保留其证据等级；未知处理史仍未知。

身份合同的变更会影响 manifest、统计设计哈希、审批和结果谱系，因此新增 session/run 语义或批量 checkpoint 复用前需要单独迁移及回归验证。
