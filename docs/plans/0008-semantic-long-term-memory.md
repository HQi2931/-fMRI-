# 语义长期记忆实施与验收计划

状态：已实现并通过本地门禁

## 目标

在现有会话记忆和滚动摘要之上实现可持久化、可解释、可管理的语义长期记忆。
已有工作已提交并推送为 ac46185；该提交是开发检查点，不表示发布门禁通过。

## 产品合同

- 会话记忆仅当前会话可见，项目记忆可被同项目其他会话召回；不跨项目共享。
- 固定记忆优先进入上下文；取消固定保留为按相关性召回的记忆。界面必须显示所有有效记忆，并解释两者区别。
- 用户手动记录可以直接确认；自动提取必须具有原始用户消息来源。模型提取的事实、科研参数和决策先作为候选，用户确认后才参与召回。
- 语义召回使用真实 embedding 和关键词融合，记录模型版本、内容版本和召回依据。未配置 embedding 时明确显示关键词降级，不宣称语义检索成功。
- 支持同义表达召回、跨会话持续保留、重要性与时间衰减、可配置过期时间，以及结果数量和上下文预算上限。
- 同作用域同键的新信息不得静默覆盖已确认事实；支持冲突展示、显式替代和重复合并，保存来源和变更审计。
- 修改使旧向量失效；忘记、拒绝、过期和替代的记忆不参与召回。忘记清除记忆正文和向量，同时处理关联摘要，防止派生内容重新注入。
- 原始聊天历史的保留与记忆遗忘分开说明；不得把记忆遗忘描述成删除全部聊天记录。
- 索引与提取失败可重试；模型网络请求不得占用数据库写事务。提交索引前比较内容版本，避免并发编辑或遗忘后旧内容复活。
- 记忆只作为用户背景与约束，不能取代文献证据、审批计划和权威工作状态。

## 实施顺序

1. 数据模型与迁移：作用域、来源、重要性、有效期、冲突/替代关系、向量版本和索引状态。
2. 独立 memory 服务：embedding 适配、关键词与向量融合、衰减、去重和生命周期。
3. 模型候选提取与应用编排：成功消息来源绑定、确认后索引、重试和并发版本检查。
4. Conversation API 和 Chat/Work 接线：项目绑定、语义召回、实际入选记忆审计、摘要失效处理。
5. 前端：新建/切换会话、项目共享范围、记忆搜索、确认/替代/合并、有效期与索引状态。
6. 修复现有回归并同步 OpenAPI、文档和变更记录，完成测试、构建、提交和推送。

## 验收证据

- API 集成测试覆盖跨会话同项目召回与跨项目隔离、未确认候选隔离、修改/遗忘/过期/替代后的排除、并发索引失效。
- 检索测试以固定向量验证同义但无词面重叠的召回；分别验证关键词降级、融合排序与阈值。
- 提取测试覆盖来源绑定、非法模型输出、事实冲突和重试去重。
- 前端测试覆盖记忆管理、会话切换、项目绑定和失败恢复；浏览器测试验证真实页面交互。
- 后端和前端完整门禁达到仓库阈值，不降低阈值；记录外部模型在线验证是否执行。
- 最终检查本地提交与远端分支一致，所有上述要求有实现和验证依据后才能完成目标。
